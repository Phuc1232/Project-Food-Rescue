1. KẾT QUẢ
- Owner (chỉ chủ store ACTIVE/SUSPENDED; mã quyền STORE_PROFILE_MANAGE không seed nên staff luôn 403):
  GET/PATCH /api/v1/stores/{storeId}/profile — xem; sửa ngay mô tả và toàn bộ giờ hoạt động (nhiều ca/ngày, ca qua nửa đêm,
  tái dùng OpeningHoursValidator) với `version` bắt buộc (cũ → 409). PATCH parse JSON thô: name/address/latitude/longitude →
  400 "Requires review", status/timezone/trường lạ → 400 nêu tên trường (UC-41 E2).
  POST/GET /api/v1/stores/{storeId}/change-requests, POST .../{requestId}/cancel — tên/địa chỉ/tọa độ (D04) thành yêu cầu
  PENDING, store không đổi; chỉ lưu trường khác giá trị hiện tại; tọa độ đi theo cặp; 0–10 tài liệu D04 tùy chọn; một PENDING
  mỗi store (khóa dòng store + unique index); owner hủy được.
  GET /api/v1/stores/{storeId}/history — lịch sử phân trang (hành động, thời điểm, vai trò OWNER/ADMIN, before/after JSON),
  không lộ id admin.
- Khách (đăng nhập bất kỳ, D10): GET /api/v1/stores/{storeId} — chỉ store ACTIVE, còn lại 404.
- Admin (ROLE_ADMIN): GET /api/v1/admin/stores (lọc status, q theo tên, phân trang), GET .../{storeId} (profile, chủ, số đợt
  và số đơn theo trạng thái, 50 lịch sử gần nhất có actorId), POST .../{storeId}/status {SUSPEND|REACTIVATE, reason};
  GET /api/v1/admin/store-change-requests (lọc status), GET .../{id}, POST .../{id}/decision {APPROVE|REJECT, reason}.
- Khóa (SUSPEND, chỉ từ ACTIVE): store SUSPENDED + status_reason + status_changed_at; đợt DRAFT/OPEN/PAUSED chưa có đơn →
  BLOCKED cùng transaction (BR-55); đợt có đơn, đơn đã xác nhận giữ nguyên (T7.5). Kích hoạt lại (chỉ từ SUSPENDED): ACTIVE,
  xóa lý do hiện hành, đợt BLOCKED vẫn BLOCKED (UC-77 A1). ADMIN không xử lý store/yêu cầu của chính mình (403).
- StoreSalesPolicy: quy tắc duy nhất "được bán / hiện cho khách" = ACTIVE; requireSellable → 409 STORE_NOT_ACTIVE. Đã ghi
  lưu ý vào card T4.3, T5.1, T5.2, T7.5.
- Lịch sử: audit_log (bất biến) với before_state/after_state; AuditService.record thêm tham số beforeState (mặc định null).
  Hành động: STORE_PROFILE_UPDATED, STORE_CHANGE_REQUESTED/CANCELLED/APPROVED/REJECTED, STORE_SUSPENDED, STORE_REACTIVATED.
- Migration V6: store.description (backfill từ businessDescription revision mới nhất), status_reason, status_changed_at;
  bảng store_change_request (+ unique index PENDING/store, CHECK PENDING ⇔ resolved_at null);
  attachment.store_change_request_id + CHECK attachment_check gồm cột mới.
- Sửa nhỏ code T3.2 (đã nêu Gate A Q6, plan P8): nộp hồ sơ ghi store.description; ApplicationDocumentValidator có
  requireMandatory (mặc định true).
- Version khi chỉ đổi ca (P1): store khóa PESSIMISTIC_WRITE, đổi ca không làm entity bẩn → EntityManager.lock(
  PESSIMISTIC_FORCE_INCREMENT) để version tăng; sửa đồng thời cùng version → một 200, một 409.
