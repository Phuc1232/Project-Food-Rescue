1. KẾT QUẢ
- Người nộp: POST /api/v1/partner-applications (201 revision mới; 200 trả nguyên revision đang chờ), GET .../me (trạng thái,
  lý do/nội dung cần bổ sung, lịch sử; không lộ người duyệt).
- Admin (ROLE_ADMIN): GET /api/v1/admin/partner-applications (lọc trạng thái, phân trang, mới nhất trước), GET .../{id}
  (store hiện hành, giờ, người nộp, tài liệu, lịch sử revision), POST .../{id}/decision APPROVE | REJECT | REQUEST_INFO.
- Mỗi lần nộp là một revision; nội dung đã nộp (tên, địa chỉ, tọa độ, múi giờ, SĐT, mô tả, giờ, tài liệu) lưu dạng snapshot JSON
  trong business_details; store giữ dữ liệu hiện hành. Từ chối/bổ sung → nộp lại tạo revision n+1.
- Tài liệu D04: bắt buộc BUSINESS_REGISTRATION, FOOD_SAFETY; tùy chọn STOREFRONT_PHOTO, OTHER; file phải do người nộp upload
  (T3.1); gắn attachment → revision. PartnerApplicationAttachmentPolicy: người nộp + ADMIN đọc được.
- Quyết định: khóa revision rồi store; chỉ revision SUBMITTED; xử lý lần hai → 409; REJECT/REQUEST_INFO bắt buộc lý do;
  APPROVE kiểm tra lại store còn PENDING_APPROVAL và không có store khác chưa đóng → store ACTIVE. ADMIN không tự xét (403).
- Migration V5: trạng thái NEEDS_INFO; unique index một revision SUBMITTED/store; unique index một store chưa đóng/chủ (D8).
- StoreAuthorizationService (Q1): ngữ cảnh owner/staff chỉ cho store khác PENDING_APPROVAL và CLOSED → người nộp không có
  quyền owner trước khi duyệt; sau duyệt GET /me có store với owner=true.
- audit/AuditService mới: PARTNER_APPLICATION_SUBMITTED / INFO_REQUESTED / REJECTED / APPROVED (actor, store_id, correlationId).
- Sửa lỗi có sẵn phát hiện khi làm: store_opening_hour lưu sai giờ (Hibernate jdbc.time_zone=UTC quy đổi LocalTime theo múi
  giờ JVM; Asia/Ho_Chi_Minh năm 1970 là +08:00 → 06:00 thành 22:00 và vi phạm CHECK). Gắn @JdbcType(LocalTimeJdbcType) cho
  opens_at/closes_at.
- Không gửi thông báo (T8.2). Được duyệt chưa mở bán (UC-61, giai đoạn 4).

4. KỊCH BẢN BẤM THỬ TRÊN SWAGGER
Chuẩn bị:
  cd CODE/backend
  docker compose up -d db && docker start foodrescue_mailpit
  sh ./gradlew bootRun --args="--spring.profiles.active=dev"
  Mở http://localhost:8080/docs ; mail thử: http://localhost:8025
  Cần 2 tài khoản: A (người nộp) và B (admin). Cấp ADMIN cho B (chỉ DB dev):
    docker exec -it foodrescue_db_container sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "insert into account_role(id,created_at,updated_at,version,account_id,role) select gen_random_uuid(),now(),now(),0,id,'"'"'ADMIN'"'"' from account where login_identifier='"'"'<email B>'"'"'"'
  (hoặc dùng lệnh bootstrap admin của dự án, xem docs/auth-setup.md).
Bước:
 1. Đăng ký/xác minh/đăng nhập A, Authorize bằng token A.
 2. Files › POST /api/v1/files 2 lần với 2 file PDF/ảnh (giấy đăng ký kinh doanh, giấy ATTP); ghi lại 2 id.
 3. Partner applications › POST /api/v1/partner-applications: dùng ví dụ "submit", thay 2 fileId → 201, store PENDING_APPROVAL,
    current.status SUBMITTED, revision 1.
 4. Gửi lại đúng request → 200, cùng current.id (không tạo trùng).
 5. Account › GET /api/v1/accounts/me → "stores": [] (chưa có quyền chủ khi chờ duyệt).
 6. Authorize bằng token B. Admin partner applications › GET /api/v1/admin/partner-applications?status=SUBMITTED → thấy hồ sơ A.
 7. GET /api/v1/admin/partner-applications/{id} → thông tin cửa hàng, giờ, tài liệu; tải tài liệu qua Files › GET .../content.
 8. POST .../{id}/decision ví dụ "requestInfo" → 200 NEEDS_INFO.
 9. Authorize lại token A: GET /api/v1/partner-applications/me → thấy NEEDS_INFO và nội dung cần bổ sung. Nộp lại (bước 3)
    → 201 revision 2, history 2.
10. Token B: POST .../{id revision 2}/decision ví dụ "approve" → 200 APPROVED, store ACTIVE. Gửi lại lần nữa → 409.
11. Token A: GET /api/v1/accounts/me → stores có cửa hàng, owner: true. POST /api/v1/partner-applications → 409.
12. Thử lỗi: token A gọi API admin → 403; decision REJECT không reason → 400 field reason.
