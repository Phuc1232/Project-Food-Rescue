1. KẾT QUẢ
- PATCH /api/v1/accounts/me: người dùng đã đăng nhập sửa displayName của chính mình (trim, 1–255 ký tự, không ký tự
  điều khiển). Không thêm số điện thoại, không migration.
- Trường không được phép (roles, stores, email, password, status, id, trường lạ) → 400 VALIDATION_FAILED, fieldErrors
  liệt kê từng trường ("Field is not editable"); không lưu phần nào, không nâng quyền (UC-06 E2).
- Dữ liệu sai → 400 VALIDATION_FAILED với field displayName/version (UC-06 E1); JSON hỏng → 400 INVALID_REQUEST.
- Chống ghi đè: body bắt buộc có version (lấy từ GET /me); lệch → 409 CONFLICT. Khóa dòng account (PESSIMISTIC_WRITE)
  trước khi so version → hai PATCH đồng thời cùng version: đúng một 200, một 409.
- Tên không đổi → 200, version giữ nguyên, không audit. Có thay đổi → audit_log action PROFILE_UPDATED (không lưu giá trị).
- GET /api/v1/accounts/me trả thêm "version" (thay đổi cộng thêm).
- CORS cho phép thêm PATCH (P1 đã duyệt) để web client khác origin gọi được.
- OpenAPI: operation patch_accounts_me (tag Account, ví dụ request/400/409), schema ProfileUpdateRequest, version trong
  AccountProfileResponse. Số paths vẫn 15.

4. KỊCH BẢN BẤM THỬ TRÊN SWAGGER
Chuẩn bị:
  cd CODE/backend
  docker compose up -d db && docker start foodrescue_mailpit
  sh ./gradlew bootRun --args="--spring.profiles.active=dev"
  Mở http://localhost:8080/docs ; mail thử: http://localhost:8025
Bước:
 1. Registration › POST /api/v1/auth/register → Try it out, email mới (vd demo-t21@example.test), mật khẩu ≥12 ký tự,
    displayName "Demo" → 201.
 2. Mở Mailpit, copy giá trị token trong link xác minh → POST /api/v1/auth/verify-email {"token":"..."} → 204.
 3. Authentication › POST /api/v1/auth/login → 200; copy accessToken → nút Authorize, dán JWT (không thêm "Bearer").
 4. Account › GET /api/v1/accounts/me → 200; ghi lại "version" (vd 1).
 5. Account › PATCH /api/v1/accounts/me, ví dụ "rename": {"displayName":"  Nguyễn Văn A  ","version":1}
    → 200, displayName "Nguyễn Văn A" (đã trim), version 2.
 6. PATCH ví dụ "forbiddenField": {"displayName":"X","version":2,"roles":["ADMIN"]}
    → 400 VALIDATION_FAILED, fieldErrors [{"field":"roles","message":"Field is not editable"}]. GET me: roles vẫn ["CUSTOMER"].
 7. PATCH {"displayName":"","version":2} → 400, fieldErrors field "displayName".
 8. PATCH {"displayName":"Khác","version":1} (version cũ) → 409 CONFLICT. GET me: tên vẫn "Nguyễn Văn A".
 9. PATCH {"displayName":"Nguyễn Văn A","version":2} (không đổi) → 200, version vẫn 2.
10. Logout (Sessions/Authentication › POST /api/v1/auth/logout) → 204; PATCH lại → 401.

5. GIỚI HẠN / LỆCH CÓ CHỦ ĐÍCH
- Endpoint này validate thủ công (ProfileUpdateRequestParser) thay vì Jakarta Validation trên DTO (P2 đã duyệt), vì
  fail-on-unknown-properties chặn trường lạ trước khi validate và không nêu tên trường.
- Audit ghi entity_type "AUTH" do AuthAuditService cố định giá trị này; action PROFILE_UPDATED phân biệt được.
- updatedAt do MutableEntity.touch() đặt bằng Instant.now() (code sẵn có, không qua Clock).
- Client (Android/web) phải gửi version khi PATCH; thiếu version → 400.
- A1 (hủy chỉnh sửa) là hành vi phía client, không có API.
