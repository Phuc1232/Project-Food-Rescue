  Tài khoản LOCKED/chưa xác minh → 409. Owner tự thêm mình → 400. Đã INVITED/ACTIVE → 409. REVOKED/DECLINED → mời lại dùng lại dòng.

  khoản không bị khóa. Thu hồi lặp → 200, không ghi trùng.
- Khóa: thêm nhân viên khóa dòng store; đổi quyền/thu hồi/chấp nhận khóa dòng phân công; tạo tài khoản trùng đồng thời → 409.
- Audit (entity STAFF_ASSIGNMENT, có store_id): STAFF_ACCOUNT_CREATED, STAFF_INVITED, STAFF_INVITATION_ACCEPTED/DECLINED,
  STAFF_PERMISSIONS_CHANGED (before/after), STAFF_REVOKED (lý do). Hiện trong lịch sử cửa hàng T3.3; vai trò người làm nay là

4. KỊCH BẢN BẤM THỬ TRÊN SWAGGER
Chuẩn bị như T3.3 (bootRun dev, /docs, Mailpit http://localhost:8025). Cần owner A có store ACTIVE (T3.2/T3.3), tài khoản C đã đăng ký.
 1. Token A: Staff › POST /api/v1/stores/{storeId}/staff ví dụ "newAccount" (email chưa tồn tại) → 201 ACTIVE, accountCreated=true.
 2. Mailpit: mở mail "Set up your FoodRescue staff account", copy token sau "#token=". Password › POST /api/v1/auth/reset-password
    {"token": "...", "newPassword": "..."} → 204. Đăng nhập bằng email mới → Account › GET /me: stores có cửa hàng, quyền đã chọn.
 3. Token A: POST .../staff với email của C → 201 INVITED. Token C: Staff › GET /api/v1/staff/assignments → thấy lời mời;
    POST .../{assignmentId}/accept → ACTIVE; GET /me có store.
 4. Token A: PUT .../staff/{assignmentId}/permissions {"permissions":["PRICE_EDIT"]} → 400; ví dụ "packAndHandover" → 200.
 5. Token C: GET /api/v1/stores/{storeId}/staff → 403.
 6. Token A: POST .../staff/{assignmentId}/revoke ví dụ "leave" → 200 REVOKED. Token C (không đăng nhập lại): GET /me → stores [].
 7. Token A: GET /api/v1/stores/{storeId}/history → STAFF_* với actorRole OWNER/STAFF.
