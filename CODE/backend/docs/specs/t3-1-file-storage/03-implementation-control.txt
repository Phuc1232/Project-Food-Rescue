1. KẾT QUẢ
- Port FileStorage + adapter LocalDiskFileStorage (thư mục FILE_STORAGE_DIR, đường dẫn <root>/ab/cd/<key>, ghi file tạm
  rồi atomic move, SHA-256 tính trong lúc ghi). Không migration.
- POST /api/v1/files (multipart, phần "file"): nhận JPEG/PNG/WebP/PDF xác định bằng magic bytes (bỏ qua Content-Type và
  đuôi tên do client gửi); ≤ 10 MB (FILE_MAX_SIZE); 201 + Location; metadata không lộ storage key/đường dẫn.
- GET /api/v1/files/{id} và /{id}/content: file chưa gắn chỉ người upload thấy; file đã gắn theo AttachmentAccessPolicy
  (chưa có policy → người upload + ADMIN). Không có quyền và không tồn tại cùng trả 404 NOT_FOUND.
- Tải về: Content-Type đã lưu, Content-Disposition attachment (UTF-8), X-Content-Type-Options nosniff,
  Cache-Control no-store, private.
- Khóa lưu 256 bit ngẫu nhiên; adapter chỉ nhận key 64 hex và kiểm tra đường dẫn nằm trong root → không path traversal.
- Lỗi DB sau khi ghi file → xóa file vừa ghi; storage lỗi → 503, không có dòng DB.
- Quota UPLOAD_ACCOUNT 30 file / 15 phút / tài khoản → 429 RATE_LIMITED + Retry-After.
- RateLimitFilter: riêng POST /api/v1/files multipart không còn bị giới hạn 16 KB; endpoint JSON giữ nguyên 16 KB.
  Trần cứng multipart 12 MB/request (FILE_MAX_REQUEST_SIZE), phần upload ghi ra file tạm, không giữ trong RAM.
- OpenAPI: tag Files, 3 path, schema FileResponse, ví dụ lỗi; upload thử được trên Swagger (nút chọn file).

4. KỊCH BẢN BẤM THỬ TRÊN SWAGGER
Chuẩn bị:
  cd CODE/backend
  docker compose up -d db && docker start foodrescue_mailpit
  sh ./gradlew bootRun --args="--spring.profiles.active=dev"
  Mở http://localhost:8080/docs ; mail thử: http://localhost:8025
  File lưu ở ~/.foodrescue/files (đặt FILE_STORAGE_DIR trong .env nếu muốn chỗ khác).
Bước:
 1. Đăng ký + xác minh + đăng nhập tài khoản A như T2.1 (register → Mailpit lấy token → verify-email → login),
    bấm Authorize, dán accessToken.
 2. Files › POST /api/v1/files → Try it out → chọn một ảnh JPG/PNG thật trên máy → Execute
    → 201; ghi lại "id", kiểm "mimeType", "sizeBytes", "checksum".
 3. Files › GET /api/v1/files/{id} với id ở bước 2 → 200 metadata.
 4. Files › GET /api/v1/files/{id}/content → 200; Swagger hiện link "Download file" → mở ra đúng ảnh.
 5. POST /api/v1/files với một file .txt hoặc .svg (kể cả đổi đuôi thành .png) → 400, fieldErrors file "Unsupported file type".
 6. POST /api/v1/files với file PDF > 10 MB → 400 "File exceeds 10485760 bytes". (File > 12 MB có thể bị đóng kết nối
    trước khi có phản hồi: hành vi chặn của trần cứng.)
 7. Đăng ký tài khoản B, Authorize bằng token của B, gọi GET /api/v1/files/{id} của A → 404 NOT_FOUND
    (giống hệt khi nhập một UUID bất kỳ).
 8. Logout/bỏ Authorize rồi gọi lại → 401.

5. GIỚI HẠN / LỆCH CÓ CHỦ ĐÍCH
- Chưa gắn file vào đối tượng nghiệp vụ; mỗi task sau (T3.2 hồ sơ đối tác, T4.1 tài liệu giá, T4.2 ảnh bìa, T4.4/T7.x
  ảnh và bằng chứng hộp, T6.5/T8.x bằng chứng hoàn/khiếu nại/chi trả) tạo attachment và cài AttachmentAccessPolicy.
- Không xóa file, không dọn file chưa gắn (đề xuất job cho T9; job phải coi box_template.cover_file_id là "đã gắn").
- Không quét virus, không xóa EXIF/GPS trong ảnh, không nén ảnh.
- File vượt trần cứng 12 MB: Tomcat có thể đóng kết nối thay vì trả 400 (hành vi bảo vệ).
- created_at/updated_at của stored_file dùng Instant.now() trong BaseEntity (code sẵn có, không qua Clock).
- Smoke trên máy dev để lại 2 file thử trong ~/.foodrescue/files và các tài khoản t31-*@example.test trong DB dev.
